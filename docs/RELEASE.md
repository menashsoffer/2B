# הפצה ל־Play: בדיקות פנימיות

## איך מוציאים גרסה

ב־GitHub פותחים Actions → Distribute → Run workflow, בוחרים בענף `main`, מוסיפים הערות שחרור בעברית אם רוצים, ולוחצים Run workflow. אם משאירים אותן ריקות, הן נוצרות מהשינויים מאז תג הגרסה הקודם.

`deploy_rules` פעיל כברירת מחדל ופורס תחילה את חוקי Firestore. `dry_run` בונה ובודק בלבד, ללא פריסת חוקים, העלאה או תג, ואפשר לבחור עבורו כל ענף. פריסת חוקים בלבד בחירום זמינה ב־Actions → Firestore rules → Run workflow.

הפצה מתוזמנת רצה ב־04:00 UTC בכל יום (06:00 בישראל בחורף, 07:00 בקיץ) רק אם יש שינויים מאז הגרסה האחרונה. אפשר לשנות את שורת ה־cron או להסיר את התזמון בקובץ `distribute.yml`. GitHub עשוי להתחיל באיחור ומשבית תזמונים לאחר 60 ימים ללא פעילות במאגר.

לאחר הפצה מוצלחת נוצרים תג `v<versionName>` ו־Release ב־GitHub, עם ה־APK וה־AAB. מספר הגרסה הוא 1000 ועוד מספר הריצה של Distribute; גם dry run צורך מספר, ופערים תקינים. אין לשנות את שם הקובץ `distribute.yml` או להעביר אותו: מספר הריצה עלול להתאפס והטלפונים ידחו גרסה נמוכה יותר.

## גרסאות
בכל ריצת Distribute קוד הגרסה הוא 1000 ועוד מספר הריצה של GitHub Actions. ה־APK וה־AAB מאותה ריצה נבנים עם אותו קוד ואותו מפתח חתימה. שם הגרסה הוא `major.minor.versionCode`, למשל `1.0.1234`. כדי לשנות את המספר הראשי או המשני, עורכים את `major` או `minor` בקובץ `version.properties` בשורש המאגר. לפני השימוש יש לוודא שהקוד הבא גבוה מכל קוד שכבר הועלה ל־Play או הופץ.

## העלאה ראשונה — ידנית
1. ב־GitHub פותחים Actions → Distribute → Run workflow, בוחרים את הענף הרצוי ומסמנים `dry_run` כדי לבנות ללא הפצה. מורידים מתוצאות הריצה את התוצר `myself-<versionCode>.aab` ומחלצים ממנו את קובץ ה־AAB.
2. ב־Play Console יוצרים את האפליקציה עם מזהה החבילה הקיים `com.aistudio.mycalculators.qvxmzt`.
3. בהגדרת Play App Signing בוחרים שימוש במפתח קיים. במחשב האישי בלבד משתמשים בכלי PEPK שמוצג ב־Play ובקובץ ה־keystore הקיים כדי לייצא את מפתח החתימה הקיים ל־Play. אין להעלות keystore, סיסמאות או מפתח פרטי למאגר או ליומני CI. אין להחליף את מפתח החתימה: רק המפתח הקיים מאפשר מעבר בין גרסת Firebase לגרסת Play ללא הסרה.
4. מעלים את ה־AAB ל־Testing → Internal testing ומוסיפים את כתובות הדוא״ל של הבודקים.

## הכנות לבודקים
ב־Play Console יש להשלים App content, כתובת URL של מדיניות פרטיות, Data safety, הצהרת financial features וקהל יעד מגיל 18 ומעלה. יש להשלים גם את יתר הדרישות שהמסוף מציג לפני שהבודקים יוכלו להתקין.

## חשבון שירות להפצות הבאות
לאחר ההעלאה הידנית, מחברים את פרויקט Google Cloud ל־Play Console ומפעילים בו Google Play Android Developer API. יוצרים חשבון שירות, מעניקים לו ב־Play Console גישה לאפליקציה עם הרשאת Release to testing tracks בלבד, ושומרים את קובץ ה־JSON כסוד GitHub Actions בשם `PLAY_SERVICE_ACCOUNT_JSON`. אין לשמור אותו במאגר או לפרסם אותו.

העלאה אוטומטית ל־Play היא שלב עתידי, אחרי ההעלאה הידנית הראשונה.

## תיקון גרסה
Play לא מאפשר להתקין גרסה עם versionCode נמוך יותר. מתקנים ומריצים הפצה חדשה עם קוד גבוה יותר.
